# Админ-панель Dreamy Stories

Веб-панель для сказок и колыбельных: добавление, редактирование, порядок, категории, переводы по гео и публикация в этот репозиторий одним коммитом. Сервер не нужен: панель — статический сайт, который сам работает с GitHub API.

## Быстрый старт (один раз)

1. **Включить GitHub Pages.** Репозиторий → Settings → Pages → Build and deployment → Source: **GitHub Actions**.
2. **Запустить сборку.** Actions → «Admin panel → GitHub Pages» → Run workflow (дальше она запускается сама при изменениях в `admin/`).
3. **Открыть панель:** `https://lobster1234t.github.io/Dreamy-Stories-Storage/` — добавьте в закладки.
4. **Создать токен** (кнопка-подсказка есть на экране входа):
   - github.com/settings/personal-access-tokens/new;
   - Repository access → Only select repositories → `Dreamy-Stories-Storage`;
   - Permissions → Repository → **Contents: Read and write**;
   - Generate token → вставить в панель.

Токен хранится только в вашем браузере. Потеряли устройство — удалите токен на той же странице GitHub.

**Запуск на своём компьютере (без GitHub Pages):** двойной клик по `admin/start-admin.cmd` — при первом запуске он сам поставит зависимости, затем откроет панель в браузере. Чтобы остановить, закройте чёрное окно.

## Как пользоваться

| Задача | Где |
|---|---|
| Добавить сказку в гео | Слева выбрать гео → «Добавить» → перетащить обложку и MP3 (название и длительность подставятся) |
| Добавить перевод существующей сказки | «Матрица переводов» → «+» в нужной клетке, или меню «⋯» у сказки → «Добавить перевод в…». Обложка и категории подставятся |
| Загрузить сразу много MP3 | «Массовая загрузка»: файл `12. Название.mp3` сам попадёт в сказку №12 |
| Добавить по ссылке (YouTube, плейлист, ссылка на MP3) | «По ссылке» → вставить ссылки → «Найти». Аудио скачается и станет MP3, сказки встанут в конец. Только в админке, запущенной через `start-admin.cmd` — см. ниже |
| Новое гео (например, PL) | Настройки → Гео → «Добавить гео» → «Скопировать список из EN» → «Массовая загрузка» MP3 |
| Поменять порядок | Перетащить за ⋮⋮ (сортировка «Как в приложении», без фильтров). Номера «12.» пересчитываются сами |
| Скрыть на время (сезонные, черновики) | Выключить «Показывать в приложении» — сказка остаётся в файле, но приложение её не видит |
| Категории | «Категории» — названия на всех языках; назначать в редакторе или выделив несколько сказок |
| Свои поля (например, «Премиум») | Настройки → Поля |
| Найти проблемы | «Проверка»: битые ссылки, пустые поля, лишние файлы, недостающие переводы |
| Опубликовать | «Опубликовать» в шапке → один коммит в `main`; приложение увидит изменения примерно через 5 минут |

- **Важно про порядок.** Текущая версия приложения запоминает избранное, скачанное и прослушанное по номеру сказки (`index`). Новые сказки добавляйте в конец; существующие не перемещайте, не скрывайте и не удаляйте из середины — иначе у пользователей всё сдвинется. Когда приложение начнёт использовать поле `id`, ограничение исчезнет.
- **Черновик не пропадает:** все правки сохраняются в браузере, пока вы не опубликуете (можно закрыть вкладку).
- **Ctrl+Z / Ctrl+Shift+Z** — отменить / повторить, **Ctrl+S** — сохранить в редакторе.
- **Песочница** (на экране входа) — те же данные, но публикация только в память браузера: можно пробовать что угодно.
- **Только просмотр** — без токена, публиковать нельзя.
- **Перед публикацией** панель предупредит, если у видимой сказки нет обложки или аудио.

## Добавить по ссылке

Работает только в админке на своём компьютере (`admin/start-admin.cmd`): скачивание делает сервер разработки на этом компьютере. На GitHub Pages это невозможно — там нет сервера, а YouTube не отдаёт файлы браузеру и блокирует облачные серверы.

1. На странице гео нажмите «По ссылке» (или «Массовая загрузка» → вкладка «По ссылке»).
2. Первый раз — «Скачать инструменты»: yt-dlp (≈25 МБ) и ffmpeg (≈30 МБ) скачаются с GitHub в `admin/.tools` (в git не попадают). Контрольные суммы проверяются; файл с неверной суммой не сохраняется.
3. Вставьте ссылки — по одной в строке; можно целый плейлист (до 200 видео). «Найти» → видео появятся в таблице и начнут скачиваться (по два одновременно). Названия чистятся от «No Copyright», хэштегов и «Bedtime Stories for Kids» — проверьте и поправьте.
4. «Добавить в черновик» → добавьте обложки в редакторе → опубликуйте.

- Сказки из ссылок всегда создаются новыми, в конце списка; ссылка на источник сохраняется в поле `source`.
- YouTube часто меняется: если скачивание перестало работать — «обновить инструменты» под полем ссылок.
- «No Copyright» в названии видео — не лицензия. Смотрите лицензию в описании (значок CC в таблице появляется, если автор указал Creative Commons на YouTube). Для CC BY нужно указывать автора; NC запрещает коммерческое использование (приложение с рекламой или подписками — коммерческое).

## Доступ для коллег

Своего входа (по почте или Gmail) у панели нет: она пускает тех, у кого есть право записи в этот репозиторий на GitHub.

1. Коллега регистрируется на github.com (можно на свой Gmail) и присылает ник.
2. Владелец: Settings → Collaborators → **Add people** → ник. В панели это кнопка «Настройки → Коллеги → Открыть доступ на GitHub».
3. Там же «Скопировать» — готовое приглашение со ссылкой на панель; отправьте его коллеге.
4. Коллега принимает приглашение и создаёт **классический** токен со scope `public_repo` (ссылка «я коллега» на экране входа). Новый тип токена GitHub не выдаёт для чужого личного репозитория.

Коллега может всё в панели: добавлять, править и публиковать. Настройки репозитория, удаление и выдача доступа остаются у владельца. Каждый коммит подписан автором — видно в истории. Закрыть доступ — Settings → Collaborators → Remove.

## Что лежит в файлах гео (для разработчика приложения)

Старый формат не изменился: `name, type, description, audioPath, imagePath, index`, и `index` всегда равен позиции в списке. Новые поля добавлены в конец — JSON-парсеры (Unity JsonUtility, Newtonsoft, Gson, Codable) их игнорируют, пока приложение их не использует.

```json
{
  "stories": [
    {
      "name": "1. Рапунцель", "type": "story", "description": "…",
      "audioPath": "stories/ru/1.mp3", "imagePath": "images/image_1.jpg", "index": 0,
      "id": "rapunzel",
      "categories": ["classic", "princesses"],
      "addedAt": "2025-09-15",
      "duration": 1741
    }
  ],
  "lullabies": [],
  "categories": [{ "id": "princesses", "name": "Принцессы", "icon": "👑", "color": "#e64980" }],
  "hidden": [{ "…": "скрытые сказки", "section": "stories", "position": 12 }]
}
```

- `id` — одинаковый у одной сказки во всех гео. Избранное и прогресс лучше хранить по нему, а не по `index`.
- `categories` у сказки — id категорий; названия на языке гео — в корневом массиве `categories`.
- `addedAt` — дата добавления (ГГГГ-ММ-ДД), `duration` — длительность в секундах.
- `hidden` — скрытые сказки; в списки `stories`/`lullabies` они не попадают.
- Свои поля из «Настройки → Поля» пишутся в сказку под своим ключом.
- `source` — страница, откуда скачано аудио (только у сказок, добавленных по ссылке).
- `admin/config.json` — настройки панели (гео, категории со всеми переводами, поля). Приложению он не нужен.

## Для разработки

```bash
cd admin
npm install
npm run dev          # http://localhost:5173
npm run test:run     # тесты
npm run coverage     # покрытие
npm run build        # сборка в admin/dist
npm run migrate -- --dry-run   # миграция данных: id, даты, длительность, категории
```

Код: `src/core` — чистая логика (разбор/сохранение JSON, проверки, изменения), `src/github` — GitHub API и песочница, `src/store` — состояние, черновики, загрузки, `src/ui` — интерфейс, `server` — плагин сервера разработки для «По ссылке» (yt-dlp + ffmpeg).

## Ограничения, о которых стоит знать

- **Файлы больше ~95 МБ** через панель не загрузить (лимит GitHub — 100 МБ). Колыбельные сейчас по 94–99 МБ — при замене их нужно сжать (например, MP3 96 кбит/с).
- **Размер репозитория уже ~4,4 ГБ** (вместе с историей). Каждый новый MP3 остаётся в истории навсегда. Когда контента станет заметно больше, аудио стоит вынести в облачное хранилище (например, Cloudflare R2) — панель для этого достаточно доработать в `src/github/backend.ts`.
- **Новое гео** приложение увидит только после обновления самого приложения (оно должно знать про `код.json`).
- После публикации GitHub отдаёт новые файлы примерно через 5 минут (кеш raw.githubusercontent.com). Новые файлы получают уникальные имена с хешем, поэтому старый кеш никогда не подменит новый файл.
